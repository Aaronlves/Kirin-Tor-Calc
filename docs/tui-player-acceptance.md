# TUI 玩家视角验收

验收日期：2026-09-01。

## 已完成的日常流程

| 玩家要做的事 | 当前入口 | 验收证据 |
| --- | --- | --- |
| 看一项结果 | 计算 | 选择中文标签与正式输出，显示精确值、近似值和单位 |
| 比较配装或天赋 | 计算 | 1–8 个命名方案，各自使用参数方案和临时输入，单个错误不清空其他结果 |
| 输入百分比 | 计算 | `暴击率=25%` 会转换为精确 `1/4` |
| 知道能调什么 | 计算 | 当前结果直接列出相关输入、正式名称、默认值和范围 |
| 反求属性断点 | 计算 | 按第一个方案和可选范围反求一个输入 |
| 看属性/目标数曲线 | 图表 | 单方案曲线和数据表共享一次扫描结果 |
| 比较方案曲线 | 图表 | 直接复用计算页方案，在同一横轴上绘制命名曲线 |
| 保存图表定义 | 图表 → 文档 | 单方案探索生成未保存的图表配置草稿，不偷偷写盘 |
| 新建机制或参数方案 | 文档 | 新建通用条目、技能/数据、组合模型、参数方案或图表配置草稿 |
| 防止丢稿 | 文档/退出 | 关闭和退出时明确选择保存、丢弃或取消；保存前校验完整工作区 |
| 找定义错误 | 诊断 | 聚合多个文件，选择后跳到文件和行；中文说明保留技术详情 |
| 理解结果来源 | 诊断 | 展开公式、输入、单位、条件和依赖文档 |
| 保存可重放结果 | 记录 | 只允许保存已落盘且校验通过的定义；记录含定义快照，可隔离重放 |
| 导出分享 | 文档 | 已保存图表配置真实写出 SVG/CSV |

自动化测试使用临时真实工作区，而不是 UI 假对象。它覆盖草稿创建与落盘、多文档原子保存、计算比较、目标反求、单/多方案图表、SVG/CSV 文件写入、跨文件诊断、运行记录与重放、窄屏布局和关闭动画。

## 玩家用语与品牌

主入口固定为“计算、图表、文档、诊断、记录”。操作使用“方案、临时参数、目标结果、反求输入、保存、校验、重放”等玩家或普通软件用语，不把操作重命名为法术、符文或其他虚构魔法词汇。

Kirin Tor 身份只通过眼形标识、紫/金/法力蓝配色、边框和克制的显现动画表达。动画不重复计算，支持完整、精简和关闭；窄终端会切换为纵向布局。

## 保留的边界

- `simplify`、`expand`、`factor` 和 `diff` 仍是高级 CLI 操作。普通玩家可通过公式说明、曲线和目标反求完成更常见的判断；目前没有把这些符号操作塞进主界面。
- 多方案交互图不能直接保存为现有单场景 Plot 文档。界面会明确阻止误存；需要长期保存比较时使用运行记录，或分别建立参数方案和图表配置。
- TUI 不提供表单式游戏数据库，也不自动同步技能、天赋或热修数值。结构化 Kirin 文档仍是唯一可写定义来源。
- TUI 不执行战斗模拟、动作优先级或最优循环搜索。

这些边界不会阻止当前目标中的期望值和等效值计算，但需要在产品说明中持续保持可见。
