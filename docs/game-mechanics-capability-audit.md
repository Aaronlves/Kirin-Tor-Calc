# 游戏机制计算能力边界

本页说明 Kirin Tor 对常见理论计算问题的适用范围。它不是游戏数据文档，也不证明任何真实游戏的系数或规则正确。

## 结论

只要一种机制能被写成有限标量公式、有限分布、有限递推、有限状态解析模型，或多资源确定性固定序列，Kirin Tor source 就能定义、校验、计算、扫描或重放它。作者也可以把外部推导出的触发率、覆盖率或期望次数作为明确输入。

Kirin Tor 不是通用战斗算法语言。它现在能逐步分析固定 sequence 的资源、动作冷却与逐枚恢复充能，但需要动态目标集合、条件优先级选择、共享冷却组、重置机制或相关随机过程才能得到结果的机制，仍不能直接建模为完整战斗循环。

“给定公式可以计算”不等于“工具能从规则说明自动推导公式”。

## 证据范围

`tests/test_game_mechanics_capabilities.py` 使用测试自身声明的虚构语义和数值构建游戏中立工作区，再执行严格校验、精确求值和扫描。相关仓库示例同样只使用虚构数据，并且不进入 wheel 或 source distribution。

这些测试只证明下列数学形状可表达、可执行；它们不证明真实游戏数据、版本或作者推导正确。

## 已证明可表达的机制形状

| 机制形状 | Kirin Tor 写法 | 能力边界 |
| --- | --- | --- |
| 概率加权期望 | 普通精确表达式 | 原生支持精确概率和有理数 |
| 阈值与分段 | `if_else` / `piecewise` | 原生支持 |
| 目标数软上限 | `piecewise`、`sqrt`、有限整数输入 | 可计算作者声明的总量曲线 |
| 固定持续时间周期效果 | `floor(duration / interval)` | 可计算明确取整规则下的等效次数 |
| 充能或冷却等效值 | 普通精确表达式 | 可计算作者给定的稳态公式 |
| 独立触发期望 | 概率与尝试频率的普通表达式 | 支持线性期望 |
| 有理减伤 | 分式表达式与单位 | 支持定义域和单位检查 |
| 层数封顶 | `min` / `max` | 原生支持 |
| 固定次数递减或连续失败 | 常数边界 `sum` / `product` | 支持有限离散展开 |
| 有限随机结果 | `distributions`、`map`、`condition` | 支持精确有限分布，不做随机采样 |
| 显式独立组合 | `independent_sum`、`repeat_sum` | 只在作者明确声明独立时组合 |
| 有限失败保护 | `recurrences` | 支持常量或静态有限整数输入决定的纯函数步数 |
| 有限状态长期值 | `state_models` 与稳态/到达查询 | 解析求解有限转移矩阵，不执行事件时间线 |
| 固定技能序列、多资源、冷却与离散充能 | `resources`、`spends`、`gains`、`cooldown`、`charges`、`cycle` | 联合推进最多 64 个资源以及动作局部冷却/逐枚恢复充能，精确判断无需等待、等待后持续或最终阻塞，并报告限制条件 |
| 多层技能/角色属性 | 封闭 `type` 对象与静态成员路径 | 支持 `entry.object.nested.leaf`；未知或缺失属性失败 |
| 等级或区间换算 | `lookup` / `interpolate` | 支持精确查表和范围内线性插值 |
| 方案比较 | entry `presets`、`compare` / `scan_compare` | 共享计算服务最多比较八个明确方案 |
| 单输入断点 | `solve` | 求有限实数解并检查输入范围 |
| 多输入平衡 | `solve-system` | 最多八个有限符号方程和变量 |
| 双输入收益面 | `grid` | 最多 10,000 个组合，结果可导出 CSV |
| 同量纲单位换算 | 精确 unit scale | 输入、范围、查表、求解和结果统一换算 |

这些能力复用同一引擎和应用服务，但不都对应公开 CLI 命令：变换、求导、求解、扫描和网格有 CLI；`compare` / `scan_compare` 当前属于共享应用与 Web 适配器操作。浏览器文档检查器只自动显示源码默认结果和源码声明的图表，不提供高级操作的通用参数表单。

## 需要作者先提供等效模型

下列机制可以在不做模拟的前提下计算，但等效参数的来源和推导不由内核负责：

- 条件动作优先级或共享冷却窗口：把期望次数或覆盖率写成输入或已推导公式；动作局部冷却和逐枚恢复充能可以直接交给确定性固定 `cycle`；
- 周期效果刷新、快照和动态更新：写出固定规则下的总次数与等效倍率；
- 窗口内累积后爆发：提供窗口内期望量与累积比例；
- 多次触发、叠层或失败保护：先抽象为有限独立重复、有限递推或封闭状态模型；
- 每目标独立衰减或重置：提供应用次数、目标状态或等效持续时间；
- 装备、天赋、目标数和战斗阶段：使用明确输入和参数方案比较，不把结果解释为自动最优搜索。

这类 source 应在说明和 `sources:` 中标明等效参数的推导来源与假设，避免把作者模型误当成游戏原始数据。

## 不能直接定义的算法

| 缺口 | 直接影响 |
| --- | --- |
| 固定循环尚无条件选择与通用事件队列 | 不能逐事件选择优先级动作，也不能表达共享冷却组、触发或冷却/充能重置；固定序列中的动作局部冷却和顺序充能已支持 |
| 没有通用联合分布构造 | 相关随机变量需要作者直接列出联合结果 |
| `sum` / `product` 只接受常数整数边界 | 不能按运行时目标数或持续时间动态循环 |
| 没有列表、向量、矩阵和目标集合 | 不能分别保存多个目标的生命、减益或快照状态 |
| 没有连续或离散全局优化器 | 可以求已定义的有限符号平衡，不能自动搜索完整配装或动作空间 |
| 没有对数、积分、极限等更广泛数学语言 | 部分闭式模型需要先在外部推导 |
| 舍入必须显式写入公式 | 多阶段服务器取整规则必须逐处建模 |
| 核心没有游戏事实或自动同步 | 技能、天赋、等级系数、热修和版本数据必须来自工作区或独立社区 Package |

这些是当前产品边界，不应包装成已经支持的能力。

## 使用判断

Kirin Tor 适合回答“两个明确方案哪个结果更高”“某输入增加多少”“什么输入达到目标值”“目标数变化时曲线如何”“给定触发率或覆盖率时等效值是多少”等问题。

它不应直接声称能够回答“按当前优先级整场实际执行多少次”“复杂循环中的真实随机分布”“多个目标各自刷新效果的最优策略”等问题。只有在这些问题先被可靠地化简为受支持的有限模型后，Kirin Tor 才负责校验和计算该模型。
