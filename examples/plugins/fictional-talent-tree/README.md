# Fictional Talent Workbench

This data-free example demonstrates all Workbench Extension Plugin v2 contribution types without
claiming to represent a real game. Install it from the bundled example workspace:

```bash
cd examples/虚构技能工作区
kt package add-path fictional_models ../packages/fictional-models
kt plugin add-path talents ../plugins/fictional-talent-tree
kt web
```

Open `组合模型.kirin`; its Preview selects the higher-priority “天赋树” renderer. The iframe can
receive the validated document projection and revision-bound Catalog summary, navigate to a
host-approved source location, evaluate an existing output with a temporary override, scan that
output over a declared input, explain and compare outputs, run a two-input grid, solve for one
declared input, and execute a named Process Analysis. The activation message also exposes the
backend-published action and limit descriptor rather than requiring the Plugin to guess host
capabilities. With two additional explicit
permissions, the renderer can read the current local buffer and the bounded template catalog. It
demonstrates all three Phase 3 boundaries: presenting a contribution-owned operation handle in the
adjacent host-owned result slot; persisting and deleting a manifest-versioned `ui.compact`
preference; and submitting an all-or-nothing Proposal 2 transaction that creates a local Build from
the locked Package template with a structured `coefficient` binding. Kirin Tor validates the whole
candidate workspace before review and again on acceptance. Acceptance creates an ordinary unsaved
draft; only the host's separate Save All flow can write it. Every request passes through the host's
identity, canonical-target, input, preset, source-size, quota and permission checks. The iframe
cannot access the host DOM, session token, workspace files, direct source mutation, run-record
creation, Package mutations, artifact export, credentials, other Plugin preference namespaces, or
the network.
